# Clash Sentinel 高保真可交互原型

本目录是 Step 7 的独立静态原型，用于冻结正式 React 看板的视觉、信息层级和交互行为。原型不连接 API，不读取 SQLite，不执行网络检测或 Shell 命令；所有内容均为内存中的虚构示例，刷新页面会恢复默认状态。

当前前端架构和运行行为见[前端设计总览](../../frontend-design.md)，后续结构拆分见[Dashboard 重构设计](../../dashboard-refactor-design.md)。本原型及固定截图是视觉与交互基准，运行代码、共享 Schema 和 API 专题才是实际行为与接口事实源。

## 预览

直接打开 [`index.html`](index.html)，或从仓库根目录启动任意静态文件服务器后访问该文件。默认展示“健康且已锁定”场景；页面顶部的“原型场景”选择器可切换异常、过期和任务状态。该选择器只用于评审，不属于正式产品。

## 信息与交互基准

- 阅读顺序固定为：连接与刷新、当前入口、运行任务、国内互联网、代理站点、候选 IP、最近事件。
- “刷新状态”仅读取快照；“立即检测”才产生健康检测任务；“重新诊断”产生严格诊断任务。
- 首页固定展示定时监测是否开启、当前为等待还是检测中、上次完成时间和下一轮时间；暂停时不虚构下一轮执行时间。
- 百度、淘宝、腾讯使用各自官方网站提供的原始品牌图片，Google、GitHub、OpenAI 使用本地矢量标识；健康情况继续通过独立状态点和文字表达。
- Google、GitHub、OpenAI 使用完全一致的可达性、HTTP 状态、总耗时和检测时间结构。OpenAI 官方服务状态作为卡片内的附加信息，不参与入口故障判断。
- apply、reset、rollback 和启用自动切换必须经过具名确认。确认期间展示订阅、当前值、目标值及风险；取消不得改变页面状态。
- 任务只展示真实阶段和任务 ID，不推算百分比。失败必须区分“已恢复”和“需人工处理”。
- 站点、入口和后台连接状态互相独立；历史成功数据过期后不能继续显示为当前健康。

## 场景覆盖

场景切换器覆盖健康、定时检测中、定时监测暂停、未锁定、无诊断、加载、过期、互联网不确定、断网、入口疑似、入口故障、代理异常、Clash 未启动、后台不可达、订阅变化、报告过期、任务运行、操作成功、失败已恢复和恢复失败。

## Step 8 定时监测 API 契约

定时监测状态已经按 [API 设计文档](../../api-design.md)的 `GET /api/monitoring` 章节完成 Step 8 实现。正式 React 看板必须读取该接口，不得通过前端计时、设置间隔或任务表猜测调度状态。原型状态与接口字段的映射如下：

- “已开启、等待下一轮”对应 `enabled=true, state=waiting`。
- “检测中”对应 `enabled=true, state=running`。
- “已暂停”对应 `enabled=false, state=disabled`。

状态条中的上次完成时间映射 `lastCompletedAt`，下一轮时间映射调度器真实返回的 `nextRunAt`。原型在检测中场景展示的“正在探测六个固定站点”仅为演示阶段文案，契约不增加 `phase` 字段；正式页面统一显示“正在执行定时检测”。定时轮次继续不写入任务表。

示例 IPv4 仅使用文档保留网段；UUID、订阅 UID、域名和时间均为虚构值。原型页面不得加入真实路径、密钥、配置正文或订阅正文。
